# Python

Подробный ликбез по Python для DevOps/SRE. Каждая тема построена одинаково: что это, зачем нужно, как работает, пример с объяснением результата и типичные ошибки. Примеры рассчитаны на Python 3.10+ (проверить версию: `python3 --version`).

Как читать: запускай примеры сам. Самый быстрый способ — интерактивная консоль `python3` (или `ipython`): вводишь строку и сразу видишь результат. В примерах результат показан в комментарии после `# →`.

## Что за язык и чем он отличается

**Интерпретируемый.** Код не компилируется заранее в исполняемый файл, как в Go или C#. Интерпретатор CPython читает `.py`-файл, переводит его в байткод (промежуточные инструкции, кэшируются в `__pycache__`) и сразу исполняет. Отсюда плюсы: не нужен шаг сборки, скрипт можно править и запускать сразу. И минусы: ошибка в редко вызываемой ветке кода всплывёт только когда до неё дойдёт выполнение, а не на этапе сборки.

**Динамическая типизация.** Тип есть у *значения*, а не у *переменной*. Переменная — просто имя (ярлык), которое можно перевесить на значение любого типа:
```python
x = 10        # x указывает на число
x = "десять"  # теперь x указывает на строку — это разрешено
```
В C# так нельзя: `int x = 10; x = "десять";` не скомпилируется.

**Строгая типизация.** При этом Python *не* превращает типы друг в друга молча, в отличие от JavaScript или Bash:
```python
"5" + 5        # → TypeError: can only concatenate str (not "int") to str
"5" + str(5)   # → '55'   — явно превратили число в строку
int("5") + 5   # → 10     — явно превратили строку в число
```
Зачем так: неявные преобразования порождают незаметные баги (в JS `"5" - 2` равно 3, а `"5" + 2` равно `"52"`). Python заставляет тебя явно сказать, что ты имеешь в виду.

**Всё — объект.** Числа, строки, функции, классы, модули — у всех есть тип, атрибуты и методы. Даже у числа: `(5).bit_length()` → 3. Функцию можно положить в переменную, передать в другую функцию или вернуть из функции. На этом построены декораторы и колбэки.

**Отступы — часть синтаксиса.** Вместо фигурных скобок `{}` блоки кода выделяются отступом (стандарт — 4 пробела). Это не стиль, а правило языка: неправильный отступ — это `IndentationError` или, хуже, код, который выполняется не в том блоке.
```python
if True:
    print("внутри if")      # 4 пробела — тело if
print("после if")           # без отступа — уже вне if
```

**Философия.** Набери в консоли `import this`, и выведется «Дзен Python». Главные идеи: явное лучше неявного, простое лучше сложного, читаемость важна. На код-ревью в Python-командах это реально используют как аргумент.

## Окружение: venv, pip, uv

**Проблема.** Проекту A нужна библиотека `requests` версии 2.25, проекту B — 2.32. Если ставить пакеты в один общий (системный) Python, они конфликтуют. Хуже того, системный Python используют утилиты самой ОС (в Ubuntu — `apt`-скрипты), и если обновить в нём библиотеку через `sudo pip install`, можно сломать систему. Поэтому современные дистрибутивы прямо запрещают `pip install` в системный Python (ошибка `externally-managed-environment`).

**Решение — виртуальное окружение (venv).** Это папка внутри проекта, где лежит своя копия интерпретатора (ссылка на него) и свои установленные пакеты. Проекты изолированы друг от друга.

```bash
python3 -m venv .venv            # создать окружение в папке .venv
source .venv/bin/activate        # «войти» в него: теперь python и pip — из .venv
which python                     # → /path/to/project/.venv/bin/python
pip install requests boto3       # пакеты ставятся только в .venv
pip freeze > requirements.txt    # записать точные версии всех пакетов
deactivate                       # выйти из окружения
```
На другой машине или в CI проект восстанавливается так: `python3 -m venv .venv && .venv/bin/pip install -r requirements.txt`. Папку `.venv` в git не коммитят (добавь её в `.gitignore`), коммитят только `requirements.txt`.

**Фиксация версий.** Если в `requirements.txt` написано просто `requests`, через полгода установится новая версия, и скрипт может сломаться. Поэтому версии фиксируют: `requests==2.32.3`. Это называется pinning, и именно это делает `pip freeze`.

**uv — современная замена.** Быстрый менеджер пакетов (написан на Rust) от Astral. Он сам создаёт venv, ставит пакеты в десятки раз быстрее pip и ведёт lock-файл.
```bash
uv init mytool && cd mytool      # новый проект с pyproject.toml
uv add requests boto3            # добавить зависимости (запишет в pyproject.toml и uv.lock)
uv run main.py                   # запустить скрипт в окружении проекта (создаст его, если нет)
uvx ruff check .                 # запустить утилиту разово, не устанавливая её в проект
```

**pyproject.toml** — современный стандартный файл описания проекта: имя, версия, зависимости, настройки инструментов (линтер, тесты). Заменяет старые `setup.py`, `setup.cfg` и отчасти `requirements.txt`.

**Инструменты качества:** `ruff` — линтер и форматтер (ищет ошибки и неиспользуемые импорты, приводит код к единому стилю), `mypy` — проверка типов (см. раздел про type hints), `pytest` — тесты.

## Переменные и имена: как это устроено на самом деле

Это фундамент, без которого непонятны многие «странности» Python.

В Python переменная — **не коробка со значением**, а **имя-ярлык, привязанный к объекту** в памяти. Присваивание `a = b` не копирует данные, а вешает второй ярлык на тот же объект.

```python
a = [1, 2, 3]
b = a            # b — второй ярлык на ТОТ ЖЕ список, копии нет
b.append(4)
print(a)         # → [1, 2, 3, 4]   — изменился и a, потому что это один объект
print(a is b)    # → True           — is проверяет: это один и тот же объект?

c = a.copy()     # а вот это настоящая копия — новый объект
c.append(5)
print(a)         # → [1, 2, 3, 4]   — a не изменился
```

**`is` против `==`:**
- `==` спрашивает: *равны ли значения?*
- `is` спрашивает: *это буквально один и тот же объект в памяти?*

```python
x = [1, 2]
y = [1, 2]
x == y   # → True   — значения одинаковые
x is y   # → False  — но это два разных списка
```
Правило: `is` используй только для сравнения с `None` (`if value is None:`), потому что `None` существует в единственном экземпляре. Для всего остального — `==`.

### 🧪 Мини-задание

**Задача.** Сначала предскажи на бумаге, потом проверь: что напечатают `a`, `b`, `c` и три сравнения, если `b = a`, `c = a.copy()`, а потом `b.append(3)`?

<details class="qa"><summary>Решение: команда и ожидаемый результат</summary>

Скопируй блок в терминал целиком:

```bash
python3 - <<'EOF'
a = [1, 2]
b = a
c = a.copy()
b.append(3)
print(a, b, c)
print(a is b, a is c, a == c)
EOF
```

Ожидаемый результат:

```text
[1, 2, 3] [1, 2, 3] [1, 2]
True False False
```

Разбор: `a` и `b` — два имени одного списка, поэтому `append` через `b` виден и через `a`, а `a is b` равно `True`. `c` — отдельная копия, сделанная *до* `append`, поэтому в ней только `[1, 2]`. Отсюда `a is c` равно `False` (разные объекты) и `a == c` тоже `False` (значения уже разошлись). Если бы копию сделали после `append`, было бы `a == c` → `True`, а `a is c` всё равно `False`.

</details>

## Базовые типы данных

### Числа: int и float
```python
count = 42              # int — целое число
big = 2 ** 100          # → 1267650600228229401496703205376
```
`int` в Python **не переполняется**: число может быть любой длины, сколько хватит памяти. В C# или Java `int` ограничен 32 битами (около 2 миллиардов), а здесь об этом думать не нужно.

```python
ratio = 0.75            # float — число с плавающей точкой (64-битный double)
0.1 + 0.2               # → 0.30000000000000004  (!)
0.1 + 0.2 == 0.3        # → False
```
Почему так: `float` хранится в двоичном виде, и десятичная 0.1 в двоичной системе — бесконечная дробь (как 1/3 в десятичной). Это не баг Python, так работают float во всех языках. Что с этим делать:
```python
import math
math.isclose(0.1 + 0.2, 0.3)       # → True — сравнение с допуском
round(0.1 + 0.2, 2)                # → 0.3
from decimal import Decimal
Decimal("0.1") + Decimal("0.2")    # → Decimal('0.3') — точная десятичная арифметика (деньги)
```

Деление и операторы:
```python
7 / 2     # → 3.5   — обычное деление ВСЕГДА даёт float
7 // 2    # → 3     — целочисленное деление (отбросить дробную часть, округление вниз)
7 % 2     # → 1     — остаток от деления (проверка чётности: n % 2 == 0)
2 ** 10   # → 1024  — возведение в степень
-7 // 2   # → -4    — внимание: округляет вниз (к минус бесконечности), а не к нулю
```
Для читаемости больших чисел можно ставить подчёркивания: `timeout_ms = 30_000`.

### Логический тип bool и «истинность»
```python
is_prod = True
has_errors = False
```
`bool` — это подкласс `int`: `True == 1`, `False == 0`. Поэтому `sum([True, False, True])` → 2. Это удобно для подсчёта: `sum(1 for p in pods if p["ready"])`, или ещё короче `sum(p["ready"] for p in pods)`.

**Truthiness (истинность значений).** В `if` и `while` можно подставить *любое* значение, а Python сам решит, считать его истинным или ложным. Ложными считаются:
- `False`, `None`
- ноль любого типа: `0`, `0.0`
- пустые коллекции: `""`, `[]`, `{}`, `()`, `set()`

Всё остальное — истинно. Это позволяет писать идиоматично:
```python
pods = []
if not pods:                # вместо if len(pods) == 0:
    print("подов нет")

name = ""
display = name or "unknown" # → 'unknown' — or возвращает первое истинное значение
```
Как работают `and`/`or`: они возвращают не `True`/`False`, а один из операндов. `a or b` вернёт `a`, если `a` истинно, иначе `b`. Поэтому `x or default` — частый способ задать значение по умолчанию. Осторожно: если `x = 0` — валидное значение, `x or 10` вернёт 10, а не 0. В таких случаях пиши явно: `x if x is not None else 10`.

### None — «значения нет»
`None` означает отсутствие значения (аналог `null`). Функция без `return` возвращает `None`. Проверяют его всегда через `is`:
```python
def find_pod(name):
    for p in pods:
        if p == name:
            return p
    # если не нашли — функция дойдёт до конца и неявно вернёт None

result = find_pod("api")
if result is None:
    print("не найден")
```

### Строки (str)
Строка — неизменяемая (immutable) последовательность Unicode-символов. Кириллица, эмодзи — всё работает «из коробки».

**Неизменяемость** значит, что методы строк не меняют строку, а возвращают *новую*:
```python
s = "Hello"
s.upper()      # → 'HELLO' — вернула новую строку
print(s)       # → 'Hello' — исходная не изменилась
s = s.upper()  # чтобы «изменить», нужно перевесить имя на результат
```

**f-строки** — основной способ подставить значения в текст (префикс `f` перед кавычками):
```python
service, port, cpu = "api", 8080, 0.4567
f"{service}:{port}"          # → 'api:8080'
f"CPU {cpu:.1%}"             # → 'CPU 45.7%'  — формат: проценты с 1 знаком
f"{cpu:.2f}"                 # → '0.46'       — 2 знака после точки
f"[{service:>10}]"           # → '[       api]' — выровнять вправо по ширине 10
f"[{service:<10}]"           # → '[api       ]' — влево
f"{port=}"                   # → 'port=8080'  — удобно для отладки: имя и значение
f"{len(service) * 2}"        # → '6'          — внутри {} может быть любое выражение
```

**Полезные методы** (каждый возвращает новую строку или значение):
```python
line = "  ERROR: disk /dev/sda1 is full  "
line.strip()                   # → 'ERROR: disk /dev/sda1 is full' — убрать пробелы по краям
line.strip().lower()           # → 'error: disk /dev/sda1 is full' — методы можно цеплять
line.strip().startswith("ERROR")   # → True
"/dev/sda1" in line            # → True — проверка подстроки
line.count("s")                # → 3 — сколько раз встречается 's'
line.replace("ERROR", "WARN")  # заменить все вхождения

"api,web,db".split(",")        # → ['api', 'web', 'db'] — разбить по разделителю
"a  b   c".split()             # → ['a', 'b', 'c'] — без аргумента: по любым пробелам, пустые выкидываются
", ".join(["api", "web"])      # → 'api, web' — склеить список строк через разделитель

"key=value=x".split("=", 1)    # → ['key', 'value=x'] — разбить только по первому '='
"key=value".partition("=")     # → ('key', '=', 'value') — всегда 3 части, даже если '=' нет
"app.tar.gz".rsplit(".", 1)    # → ['app.tar', 'gz'] — разбить справа
```
Частая ошибка: `", ".join([1, 2])` упадёт с `TypeError`, потому что `join` склеивает только строки. Нужно сначала превратить: `", ".join(str(x) for x in [1, 2])`.

**Индексы и срезы.** Индексы начинаются с 0, отрицательные считаются с конца:
```python
s = "kubernetes"
s[0]      # → 'k'      — первый символ
s[-1]     # → 's'      — последний
s[0:4]    # → 'kube'   — срез [начало:конец), конец НЕ включается
s[4:]     # → 'rnetes' — от 4 до конца
s[:4]     # → 'kube'   — с начала до 4
s[::2]    # → 'kbree'  — каждый второй символ (индексы 0, 2, 4, 6, 8) (третий параметр — шаг)
s[::-1]   # → 'setenrebuk' — шаг -1 разворачивает строку
```
Срезы работают одинаково для строк, списков и кортежей. Почему конец не включается: так `s[:4] + s[4:]` всегда даёт исходную строку, а длина среза `s[a:b]` равна `b - a`.

**Многострочные и raw-строки:**
```python
query = """
SELECT *
FROM pods
"""                         # тройные кавычки — строка с переносами

pattern = r"\d+\.\d+"       # raw-строка: \ не экранирует. Нужна для регулярных выражений и путей Windows
```

**str и bytes.** `str` — текст (символы), `bytes` — сырые байты (то, что реально идёт по сети и лежит в файле). Перевод между ними — кодирование: `"привет".encode("utf-8")` → bytes, `b"\xd0\xbf".decode("utf-8")` → str. Встречается при работе с `subprocess` (без `text=True` вывод приходит как bytes), сокетами, base64:
```python
import base64
base64.b64decode("cGFzc3dvcmQ=").decode()   # → 'password' — так декодируют k8s Secret
```

### Преобразование типов
```python
int("42")        # → 42
int("42.5")      # → ValueError — строку с точкой в int напрямую нельзя
int(float("42.5"))  # → 42
float("1e3")     # → 1000.0
str(3.14)        # → '3.14'
bool("False")    # → True (!) — непустая строка всегда истинна, текст не анализируется
list("abc")      # → ['a', 'b', 'c']
int("ff", 16)    # → 255 — из шестнадцатеричной системы
type(42)         # → <class 'int'>
isinstance(42, int)          # → True — правильный способ проверить тип
isinstance(True, int)        # → True — потому что bool — подкласс int
```
Ловушка `bool("False")` реально встречается при чтении переменных окружения: `os.environ["DEBUG"]` — всегда строка. Правильно: `debug = os.getenv("DEBUG", "false").lower() in ("1", "true", "yes")`.

### Изменяемые и неизменяемые типы — почему это важно

| Неизменяемые (immutable) | Изменяемые (mutable) |
|---|---|
| `int`, `float`, `bool`, `str`, `bytes`, `tuple`, `frozenset`, `None` | `list`, `dict`, `set`, `bytearray`, объекты твоих классов |

Неизменяемый объект нельзя поменять «на месте»: любая операция создаёт новый объект. Изменяемый меняется на месте, и это изменение видят **все** имена, которые на него указывают.

Где это стреляет:
1. **Передача в функцию.** Функция получает ссылку на тот же объект. Если она изменит список, изменится и список снаружи.
   ```python
   def add_default_tag(tags):
       tags.append("managed-by-python")   # меняет исходный список!

   my_tags = ["prod"]
   add_default_tag(my_tags)
   print(my_tags)   # → ['prod', 'managed-by-python']
   ```
2. **Ключи словаря.** Ключом `dict` (и элементом `set`) может быть только *хешируемый* объект, а хешируемы, по сути, неизменяемые. `{[1, 2]: "x"}` → `TypeError: unhashable type: 'list'`. Кортеж можно: `{("us-east-2", "prod"): "vpc-123"}`.
3. **Значения по умолчанию в функциях** (см. раздел «Функции» — классическая ловушка).

## Коллекции

Коллекции — контейнеры для нескольких значений. Выбор правильной — половина хорошего кода.

### list — список
Упорядоченная изменяемая последовательность. Аналог `List<T>` в C#, но может хранить значения разных типов.
```python
pods = ["api", "web"]
pods.append("db")              # добавить в конец         → ['api', 'web', 'db']
pods.extend(["cache", "mq"])   # добавить несколько       → [..., 'cache', 'mq']
pods.insert(0, "lb")           # вставить по индексу      → ['lb', 'api', ...]
last = pods.pop()              # снять последний и вернуть → 'mq'
first = pods.pop(0)            # снять по индексу          → 'lb'
pods.remove("web")             # удалить по ЗНАЧЕНИЮ (первое вхождение), ValueError если нет
"api" in pods                  # → True — проверка наличия
pods.index("db")               # → позиция элемента
len(pods)                      # → длина
pods[0] = "api-v2"             # изменить элемент
```
`append` против `extend`: `pods.append(["x", "y"])` добавит *один* элемент — вложенный список. `pods.extend(["x", "y"])` добавит *два* элемента.

**Сортировка:**
```python
nums = [3, 1, 2]
sorted(nums)             # → [1, 2, 3] — возвращает НОВЫЙ список, nums не меняется
nums.sort()              # сортирует НА МЕСТЕ, возвращает None
result = nums.sort()     # частая ошибка: result будет None

pods = [{"name": "api", "restarts": 5}, {"name": "web", "restarts": 12}]
sorted(pods, key=lambda p: p["restarts"], reverse=True)
# key — функция, которая для каждого элемента говорит, ПО ЧЕМУ сравнивать
# → [{'name': 'web', 'restarts': 12}, {'name': 'api', 'restarts': 5}]
```

**Скорость:** доступ по индексу и `append` — мгновенно (O(1) — «О большое», запись того, как время операции растёт с размером данных: O(1) — не зависит от размера, O(n) — растёт пропорционально числу элементов). А вот `in` и `remove` перебирают весь список (O(n)): на миллионе элементов это заметно. Если нужно часто проверять «есть ли элемент» — используй `set`.

### tuple — кортеж
Как список, но **неизменяемый**. Зачем, если есть список:
- обозначает «запись» с фиксированной структурой: `("10.0.0.1", 22)` — хост и порт;
- может быть ключом словаря и элементом множества (хешируемый);
- защищает данные от случайного изменения.

```python
endpoint = ("10.0.0.1", 22)
host, port = endpoint          # распаковка: разложить кортеж по переменным
print(host)                    # → '10.0.0.1'

def min_max(values):
    return min(values), max(values)   # функция «возвращает два значения» — на самом деле один кортеж
lo, hi = min_max([3, 1, 4])           # → lo=1, hi=4

first, *rest = [1, 2, 3, 4]    # звёздочка собирает «всё остальное» → first=1, rest=[2, 3, 4]
a, b = b, a                    # обмен значений без временной переменной
single = ("only",)             # кортеж из одного элемента — нужна запятая! ("only") — это просто строка
```

### dict — словарь
Хранит пары **ключ → значение**. Основная структура данных в Python: JSON, YAML, конфиги, ответы API — всё превращается в словари. Внутри это хеш-таблица, поэтому поиск по ключу мгновенный (O(1)) независимо от размера. С Python 3.7 словарь **сохраняет порядок добавления** ключей.

```python
cfg = {"env": "prod", "replicas": 3}

cfg["region"] = "us-east-2"   # добавить или перезаписать ключ
cfg["env"]                    # → 'prod'
cfg["timeout"]                # → KeyError — такого ключа нет, программа упадёт
cfg.get("timeout")            # → None — безопасный доступ, без ошибки
cfg.get("timeout", 30)        # → 30 — со значением по умолчанию
"env" in cfg                  # → True — проверка ключа (не значения!)
del cfg["region"]             # удалить ключ (KeyError, если нет)
cfg.pop("region", None)       # удалить без ошибки, вернуть значение или None

# перебор
for key in cfg:                     # по умолчанию перебираются ключи
    print(key)
for key, value in cfg.items():      # ключи и значения сразу — самый частый вариант
    print(f"{key} = {value}")
list(cfg.keys()), list(cfg.values())

# слияние (3.9+): правый словарь перезаписывает совпадающие ключи
defaults = {"replicas": 1, "timeout": 30}
override = {"replicas": 3}
final = defaults | override         # → {'replicas': 3, 'timeout': 30}
# старый способ: {**defaults, **override}
```

**setdefault** — «получить значение, а если ключа нет, сначала создать его с этим значением». Удобно для группировки:
```python
by_ns = {}
for name, ns in [("api", "prod"), ("web", "prod"), ("db", "data")]:
    by_ns.setdefault(ns, []).append(name)
# → {'prod': ['api', 'web'], 'data': ['db']}
```

**Вложенные структуры** — так выглядит распарсенный JSON от `kubectl get pod -o json`:
```python
pod = {
    "metadata": {"name": "api-7d9f", "labels": {"app": "api"}},
    "status": {"containerStatuses": [{"name": "app", "restartCount": 3}]},
}
pod["metadata"]["labels"]["app"]                  # → 'api'
pod["status"]["containerStatuses"][0]["restartCount"]   # → 3
# безопасный доступ, если ключа может не быть:
pod.get("spec", {}).get("nodeName", "не назначен")   # → 'не назначен'
```

### set — множество
Неупорядоченный набор **уникальных** значений. Зачем:
- убрать дубликаты: `set(["a", "b", "a"])` → `{'a', 'b'}`;
- быстрая проверка «есть ли элемент» (O(1), как в dict);
- операции над множествами — «что есть там, но нет здесь».

```python
running = {"api", "web", "worker"}
expected = {"api", "web", "db"}

expected - running    # → {'db'}             — чего не хватает (ожидали, но не запущено)
running - expected    # → {'worker'}         — что лишнее
running & expected    # → {'api', 'web'}     — пересечение: есть и там, и там
running | expected    # → все четыре          — объединение
running ^ expected    # → {'db', 'worker'}   — есть только в одном из двух

empty = set()         # пустое множество. {} — это пустой СЛОВАРЬ, не множество!
running.add("cron"); running.discard("nope")   # discard не падает, если элемента нет
```
Пример из жизни: сравнить список серверов в инвентаре Ansible и реально запущенных EC2-инстансов — это ровно разность множеств.

### Модуль collections — специализированные коллекции
```python
from collections import Counter, defaultdict, deque

# Counter — словарь-счётчик: считает, сколько раз встретился каждый элемент
codes = ["200", "500", "200", "404", "200"]
c = Counter(codes)            # → Counter({'200': 3, '500': 1, '404': 1})
c.most_common(2)              # → [('200', 3), ('500', 1)] — топ-2
c["502"]                      # → 0 — для отсутствующего ключа не KeyError, а 0

# defaultdict — словарь, который сам создаёт значение для нового ключа
groups = defaultdict(list)    # для нового ключа автоматически создаст []
groups["prod"].append("api")  # не нужно проверять, есть ли ключ
# → defaultdict(<class 'list'>, {'prod': ['api']})

# deque — двусторонняя очередь; maxlen — хранит только последние N элементов
last_lines = deque(maxlen=3)
for line in ["a", "b", "c", "d"]:
    last_lines.append(line)
# → deque(['b', 'c', 'd']) — аналог tail -n 3
```

### Какую коллекцию выбрать
| Задача | Коллекция |
|---|---|
| Упорядоченный набор, который будет меняться | `list` |
| Фиксированная «запись», ключ словаря, возврат нескольких значений | `tuple` |
| Поиск по ключу, конфиг, JSON | `dict` |
| Уникальность, быстрый `in`, сравнение наборов | `set` |
| Подсчёт частоты | `Counter` |
| Группировка | `defaultdict(list)` |
| Последние N элементов, очередь | `deque` |

**Задача.** Есть ожидаемые сервисы (`api`, `web`, `db`), реально запущенные (`api`, `web`, `worker` и ещё раз `web`) и список HTTP-статусов. Найди, каких сервисов не хватает, какие лишние, какие запущены дважды, топ-2 статусов и сгруппируй статусы по классам `2xx`/`4xx`/`5xx`.

```bash

print("missing:", sorted(expected - set(running)))
print("extra:  ", sorted(set(running) - expected))

Дубликаты находит `Counter`: у `web` счётчик 2. `most_common(2)` возвращает пары «значение — количество». `defaultdict(list)` создаёт пустой список для нового ключа, поэтому группировка обходится без проверок `if key in`.

## Условия и циклы

### if / elif / else
```python
code = 503
if code < 300:
    status = "ok"
elif code < 500:          # elif = else if; проверяется, только если предыдущие условия ложны
    status = "client error"
else:
    status = "server error"

# тернарный оператор — if в одно выражение
status = "ok" if code < 400 else "fail"

# цепочка сравнений — читается как в математике
if 200 <= code < 300:
    print("2xx")

# проверка вхождения вместо цепочки or
if env in ("prod", "production"):     # вместо env == "prod" or env == "production"
    print("осторожно, прод")
```

### for — перебор коллекции
В Python `for` перебирает **элементы**, а не индексы (как `foreach` в C#):
```python
for pod in ["api", "web"]:
    print(pod)

# если нужен и индекс — enumerate (не range(len(...)))
for i, pod in enumerate(["api", "web"], start=1):
    print(f"{i}. {pod}")     # → 1. api / 2. web

# параллельный перебор двух списков — zip
names = ["api", "web"]
ips = ["10.0.0.1", "10.0.0.2"]
for name, ip in zip(names, ips):
    print(name, ip)
# zip останавливается на самом коротком списке; strict=True (3.10+) упадёт, если длины разные

# числа — range(начало, конец, шаг), конец НЕ включается
for i in range(5):          # 0, 1, 2, 3, 4
    print(i)
for i in range(10, 0, -2):  # 10, 8, 6, 4, 2
    print(i)
```

### while, break, continue и else у цикла
```python
attempts = 0
while attempts < 5:
    attempts += 1               # в Python нет ++ ; пишут += 1
    if attempts == 2:
        continue                # перейти к следующей итерации, пропустив код ниже
    if check_health():
        print("сервис поднялся")
        break                   # выйти из цикла
else:
    # else у цикла выполняется, если цикл закончился САМ, без break
    raise RuntimeError("сервис не поднялся за 5 попыток")
```
`else` у цикла сбивает с толку, но полезен именно для поиска и повторных попыток: «если перебрали всё и не нашли (не было break) — сделать то-то».

### match — сопоставление с образцом (3.10+)
Похож на `switch`, но умеет разбирать структуру данных:
```python
def handle(event: dict) -> str:
    match event:
        case {"type": "deploy", "env": "prod"}:
            return "деплой в прод — нужен апрув"
        case {"type": "deploy", "env": env}:      # env «вытаскивается» из словаря в переменную
            return f"деплой в {env}"
        case {"type": "alert", "severity": "critical" | "high"}:   # | — «или»
            return "будим дежурного"
        case _:                                   # _ — всё остальное (default)
            return "игнорируем"

handle({"type": "deploy", "env": "stage"})   # → 'деплой в stage'
```

### Оператор «морж» `:=`
Присваивает значение и сразу возвращает его. Нужен, чтобы не вычислять одно и то же дважды:
```python
import re
if (m := re.search(r"took (\d+)ms", line)) is not None:
    print(int(m.group(1)))
# без моржа пришлось бы: m = re.search(...); if m is not None: ...
```

### 🧪 Мини-задание

**Задача.** Напиши цикл ожидания: до 5 попыток проверить «здоровье» сервиса, выйти при успехе, а если все попытки неудачны — сообщить об этом через `else` у цикла. Проверь два сценария: сервис поднимается на 3-й попытке и не поднимается вовсе. Затем классифицируй коды 204, 301, 404, 503 через `match`.

<details class="qa"><summary>Решение: команда и ожидаемый результат</summary>

Скопируй блок в терминал целиком:

```bash
python3 - <<'EOF'
def make_check(ok_on):
    calls = {"n": 0}
    def check():
        calls["n"] += 1
        return calls["n"] == ok_on
    return check

for ok_on in (3, 99):
    check = make_check(ok_on)
    for attempt in range(1, 6):
        if check():
            print(f"up on attempt {attempt}")
            break
    else:
        print("still down after 5 attempts")

for code in (204, 301, 404, 503):
    match code:
        case 200 | 201 | 204:
            kind = "ok"
        case c if 300 <= c < 400:
            kind = "redirect"
        case c if c >= 500:
            kind = "server error"
        case _:
            kind = "client error"
    print(code, kind)
EOF
```

Ожидаемый результат:

```text
up on attempt 3
still down after 5 attempts
204 ok
301 redirect
404 client error
503 server error
```

Разбор: в первом сценарии срабатывает `break`, и `else` пропускается. Во втором цикл доходит до конца сам, без `break`, поэтому выполняется `else`. Это ровно тот паттерн «повторить N раз, иначе ошибка», что в разделе. В `match` порядок `case` важен: проверяется первый подходящий, а `case _` ловит всё остальное. Условия `if` после образца (guard) позволяют проверять диапазоны.

</details>

## Comprehensions — построение коллекций в одну строку

Comprehension — компактная запись цикла, который строит новую коллекцию. Это идиоматичный Python: такой код обычно короче, читается проще и работает быстрее, чем `for` с `append`.

```python
# обычный цикл:
squares = []
for x in range(10):
    if x % 2 == 0:
        squares.append(x * x)

# то же самое через list comprehension:
squares = [x * x for x in range(10) if x % 2 == 0]   # → [0, 4, 16, 36, 64]
# читается так: «x*x для каждого x из range(10), если x чётный»
```

Виды:
```python
pods = [
    {"name": "api", "ns": "prod", "restarts": 0},
    {"name": "web", "ns": "prod", "restarts": 7},
    {"name": "etl", "ns": "data", "restarts": 2},
]
names = [p["name"] for p in pods]                       # list  → ['api', 'web', 'etl']
by_name = {p["name"]: p["restarts"] for p in pods}      # dict  → {'api': 0, 'web': 7, 'etl': 2}
namespaces = {p["ns"] for p in pods}                    # set   → {'prod', 'data'}
broken = [p["name"] for p in pods if p["restarts"] > 5] # с фильтром → ['web']
labels = ["ok" if p["restarts"] == 0 else "check" for p in pods]   # if-else стоит ДО for
```
Когда **не** использовать: если внутри сложная логика, несколько условий или побочные эффекты (запись в файл, вызов API). Comprehension должен строить коллекцию, а не «делать действия». Если строка не читается с первого раза — пиши обычный цикл.

### 🧪 Мини-задание

**Задача.** Из списка подов одной строкой на каждый пункт построй: словарь «имя → рестарты» только для `prod`; отсортированный список namespace без повторов; список «шумных» подов (больше 5 рестартов); метки вида `api:ok` / `web:check`.

<details class="qa"><summary>Решение: команда и ожидаемый результат</summary>

Скопируй блок в терминал целиком:

```bash
python3 - <<'EOF'
pods = [
    {"name": "api", "ns": "prod", "restarts": 0},
    {"name": "web", "ns": "prod", "restarts": 7},
    {"name": "etl", "ns": "data", "restarts": 2},
    {"name": "cron", "ns": "data", "restarts": 9},
]
prod = {p["name"]: p["restarts"] for p in pods if p["ns"] == "prod"}
namespaces = sorted({p["ns"] for p in pods})
noisy = [p["name"] for p in pods if p["restarts"] > 5]
labels = [f'{p["name"]}:{"ok" if p["restarts"] == 0 else "check"}' for p in pods]
print(prod)
print(namespaces)
print(noisy)
print(labels)

```

Ожидаемый результат:

```text

['web', 'cron']
['api:ok', 'web:check', 'etl:check', 'cron:check']
```

Разбор: фильтр `if` в конце comprehension отбрасывает элементы, а `if … else` *перед* `for` выбирает значение для каждого элемента. Это два разных синтаксиса, на собеседовании их путают. Set comprehension убрал повтор `prod`/`data`, а `sorted` сделал вывод стабильным.

## Генераторы — ленивые последовательности

**Проблема.** Нужно обработать лог на 20 GB. `open(...).readlines()` прочитает весь файл в список и съест 20+ GB памяти.

**Решение — генератор.** Он отдаёт значения **по одному, по запросу**, и в памяти в каждый момент только одно значение.

Генераторное выражение — как list comprehension, но в круглых скобках:
```python
total = sum(len(line) for line in open("huge.log"))   # память — на одну строку, а не на весь файл
nums = (x * x for x in range(10**9))                  # создаётся мгновенно — ничего ещё не посчитано
next(nums)   # → 0 — вычисляет следующее значение только по запросу
```

Генераторная функция — функция с `yield` вместо `return`. Каждый `yield` отдаёт значение и *приостанавливает* функцию до следующего запроса:
```python
def read_errors(path):
    """Отдаёт строки с ERROR по одной, не держа файл в памяти."""
    with open(path) as f:
        for line in f:                    # файл тоже читается построчно — лениво
            if "ERROR" in line:
                yield line.rstrip()       # отдать строку и «заснуть» до следующего запроса

def only_db(lines):
    for line in lines:
        if "database" in line:
            yield line

# генераторы можно соединять в конвейер, как пайпы в bash: cat | grep | grep
for line in only_db(read_errors("/var/log/app.log")):
    print(line)
```
Важно: генератор проходится **один раз**. После того как его перебрали, он пуст: второй `for` по нему ничего не выведет. Если нужен повторный проход — превращай в список `list(gen)` (если помещается в память) или создавай генератор заново.

Пример из DevOps — пагинация API как генератор: вызывающий код просто перебирает объекты, не думая о страницах:
```python
def all_projects(session, url):
    page = 1
    while True:
        r = session.get(url, params={"page": page, "per_page": 100}, timeout=10)
        r.raise_for_status()
        items = r.json()
        if not items:
            return            # return в генераторе — конец последовательности
        yield from items      # отдать каждый элемент списка по очереди
        page += 1
```

## Функции

### Объявление, аргументы, возврат
```python
def scale(service: str, replicas: int = 1) -> str:
    """Масштабирует сервис. Это docstring — описание функции, видно в help(scale)."""
    return f"{service} -> {replicas}"

scale("api")                    # → 'api -> 1'   — replicas взят по умолчанию
scale("api", 3)                 # → 'api -> 3'   — позиционные аргументы
scale(replicas=3, service="api")  # именованные аргументы — порядок не важен, читаемее
```
`: str` и `-> str` — подсказки типов (type hints). Python их **не проверяет** при выполнении, они для читателя, IDE и mypy (статический анализатор: проверяет типы по подсказкам без запуска кода, обычно в CI).

### *args и **kwargs — произвольное число аргументов
```python
def log(level, *messages, **fields):
    # *messages собирает все «лишние» позиционные аргументы в КОРТЕЖ
    # **fields собирает все «лишние» именованные аргументы в СЛОВАРЬ
    print(level, messages, fields)

log("INFO", "deploy", "started", service="api", env="prod")
# → INFO ('deploy', 'started') {'service': 'api', 'env': 'prod'}
```
Имена `args`/`kwargs` — соглашение, важны только `*` и `**`. Главное применение — функции-обёртки и декораторы, которые принимают «что угодно» и передают дальше: `func(*args, **kwargs)`.

Обратная операция — **распаковка** при вызове:
```python
params = {"service": "web", "replicas": 2}
scale(**params)              # то же, что scale(service="web", replicas=2)
args = ["web", 2]
scale(*args)                 # то же, что scale("web", 2)
```

**Только именованные аргументы.** Всё, что стоит после `*` в объявлении, можно передать только по имени:
```python
def delete_namespace(name, *, force=False):
    args = ["kubectl", "delete", "namespace", name]
    if force:
        args += ["--grace-period=0", "--force"]
    subprocess.run(args, check=True)
delete_namespace("dev", True)        # → TypeError
delete_namespace("dev", force=True)  # ок — по вызову сразу видно, что за True
```
Зачем: вызов `delete_namespace("dev", True)` нечитаем — что значит `True`? Для флагов это хорошая практика.

### Ловушка: изменяемое значение по умолчанию
Самый частый вопрос про функции на собеседовании.
```python
def add_tag(tag, tags=[]):
    tags.append(tag)
    return tags

add_tag("a")   # → ['a']
add_tag("b")   # → ['a', 'b']   (!) ожидали ['b']
```
**Почему:** значение по умолчанию вычисляется **один раз**, в момент определения функции (когда Python выполняет строку `def`), а не при каждом вызове. Все вызовы без аргумента получают *один и тот же* список и накапливают в нём данные.

**Как правильно:** использовать `None` как маркер «не передали» и создавать новый объект внутри:
```python
def add_tag(tag, tags=None):
    if tags is None:
        tags = []          # новый список при КАЖДОМ вызове
    tags.append(tag)
    return tags
```
То же касается `{}` и `set()` по умолчанию.

### Область видимости: LEGB
Когда Python встречает имя, он ищет его по порядку:
1. **L**ocal — внутри текущей функции;
2. **E**nclosing — во внешней функции (если функция вложенная);
3. **G**lobal — на уровне модуля (файла);
4. **B**uilt-in — встроенные имена (`len`, `print`, `list`).

```python
counter = 0
def increment():
    counter += 1     # UnboundLocalError!
```
Почему ошибка: присваивание внутри функции делает `counter` *локальной* переменной на всю функцию, а прочитать её до присваивания нельзя. Чтобы изменить глобальную, нужно `global counter`. Но лучше так не делать: глобальное состояние усложняет код и тесты. Передавай значения аргументами и возвращай через `return`.

Ещё ловушка: не называй переменные именами встроенных функций (`list = [1, 2]`, `id = 5`, `type = "x"`). Ты «перекроешь» встроенную функцию, и `list("abc")` дальше в файле сломается.

### lambda — короткая анонимная функция
```python
square = lambda x: x * x          # то же, что def square(x): return x * x
sorted(pods, key=lambda p: p["restarts"])
```
Ограничение: только одно выражение, без операторов. Используется там, где нужна маленькая функция «на месте» — в `key=` для сортировки, `max`, `min`, `filter`. Если логика сложнее — пиши обычную `def`.

### Замыкания
Вложенная функция «запоминает» переменные внешней функции, даже когда внешняя уже завершилась:
```python
def make_prefixer(prefix):
    def add_prefix(name):
        return f"{prefix}-{name}"    # prefix взят из внешней функции
    return add_prefix                # возвращаем саму функцию, не вызывая её

prod = make_prefixer("prod")
prod("api")    # → 'prod-api'
```
На замыканиях построены декораторы.

## Декораторы

**Проблема.** Нужно, чтобы десяток функций, вызывающих API, повторяли попытки при сетевых ошибках. Копировать цикл retry в каждую — плохо.

**Решение.** Декоратор — функция, которая принимает функцию и возвращает *новую* функцию с добавленным поведением. Синтаксис `@decorator` над `def` — сокращение для `func = decorator(func)`.

Простейший декоратор — замер времени выполнения:
```python
import functools
import time

def timed(func):
    @functools.wraps(func)                # сохранить имя и docstring исходной функции
    def wrapper(*args, **kwargs):         # принимает любые аргументы...
        start = time.perf_counter()
        result = func(*args, **kwargs)    # ...и передаёт их исходной функции
        print(f"{func.__name__} заняла {time.perf_counter() - start:.2f}s")
        return result
    return wrapper

@timed
def backup():
    time.sleep(1)

backup()   # → backup заняла 1.00s
```
Без `functools.wraps` у обёрнутой функции имя станет `wrapper`, и это запутает логи и отладку.

Декоратор с параметрами — нужен ещё один уровень вложенности (функция, которая *возвращает* декоратор):
```python
def retry(times=3, delay=1.0, exceptions=(Exception,)):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            for attempt in range(1, times + 1):
                try:
                    return func(*args, **kwargs)
                except exceptions as e:
                    if attempt == times:
                        raise                          # попытки кончились — пробросить ошибку
                    wait = delay * 2 ** (attempt - 1)  # экспоненциальная задержка: 1, 2, 4, 8 с
                    print(f"{func.__name__}: попытка {attempt} не удалась ({e}), жду {wait}s")
                    time.sleep(wait)
        return wrapper
    return decorator

@retry(times=5, exceptions=(ConnectionError, TimeoutError))
def fetch_status():
    return requests.get("https://api.example.com/status", timeout=5).json()
```
Почему экспоненциальная задержка: если сервис перегружен, частые повторы от всех клиентов добьют его окончательно. Растущая пауза даёт ему восстановиться. В проде ещё добавляют случайный разброс (jitter), чтобы клиенты не повторяли запросы синхронно.

Встроенные декораторы, которые нужно знать:
- `@functools.cache` / `@functools.lru_cache(maxsize=128)` — запоминает результат для одинаковых аргументов (мемоизация);
- `@property` — метод, который вызывается как атрибут (`svc.is_ha` без скобок);
- `@staticmethod`, `@classmethod` — см. раздел про классы;
- `@dataclass` — генерирует методы класса.

## Исключения

**Зачем.** Ошибка (нет файла, сеть недоступна, неверный JSON) прерывает выполнение и «летит» вверх по стеку вызовов, пока её кто-то не перехватит. Если никто не перехватил — программа падает с traceback (трассировкой: какая функция какую вызвала и где упало).

```python
import json

raw = '{"replicas": 3'   # битый JSON — нет закрывающей скобки
try:
    cfg = json.loads(raw)
except json.JSONDecodeError as e:          # ловим КОНКРЕТНЫЙ тип ошибки
    print(f"конфиг битый: {e}")
    cfg = {"replicas": 1}                  # и решаем, что делать: значение по умолчанию
else:
    print("конфиг прочитан")               # выполняется, только если исключения НЕ было
finally:
    print("выполнится всегда")             # закрыть ресурсы, снять блокировку
```

Перехват нескольких типов и проброс дальше:
```python
try:
    value = cfg["timeout"] / int(cfg["retries"])
except (KeyError, ValueError) as e:
    print(f"кривой конфиг: {e!r}")
except ZeroDivisionError:
    value = 0
except Exception:
    log.exception("неожиданная ошибка")    # запишет сообщение И traceback
    raise                                  # пробросить ту же ошибку выше — не «проглатывать»
```

Свои исключения — для понятных ошибок предметной области:
```python
class DeployError(Exception):
    """Ошибка деплоя."""

def deploy(service):
    try:
        run_helm(service)
    except subprocess.CalledProcessError as e:
        raise DeployError(f"helm упал для {service}") from e
        # from e сохраняет исходную причину: в traceback будут обе ошибки
```

**Правила:**
- Лови **конкретные** исключения. Голый `except:` ловит вообще всё, включая `KeyboardInterrupt` (Ctrl+C) и `SystemExit`, и скрипт перестанет нормально останавливаться.
- Не «глотай» ошибки молча (`except Exception: pass`). Это худший вариант: что-то сломалось, а ты об этом не узнаешь.
- **EAFP против LBYL.** В Python принято «сначала попробовать, потом обработать ошибку» (EAFP), а не «проверить всё заранее» (LBYL):
  ```python
  # LBYL: проверка заранее. Между проверкой и открытием файл могут удалить (race condition)
  if os.path.exists(path):
      data = open(path).read()
  # EAFP: просто пробуем
  try:
      data = open(path).read()
  except FileNotFoundError:
      data = ""
  ```

Основные встроенные исключения: `ValueError` (неверное значение: `int("abc")`), `TypeError` (неверный тип), `KeyError` (нет ключа в dict), `IndexError` (нет индекса в list), `FileNotFoundError`, `PermissionError`, `TimeoutError`, `ConnectionError`, `AttributeError` (нет атрибута у объекта, часто — когда переменная неожиданно `None`).

Разбор: вызывающий код ловит только `ConfigError` и не обязан знать про `json` и `KeyError`. При этом исходная ошибка не потеряна: `from e` кладёт её в `__cause__`, и в traceback будут видны обе. `e.pos` показывает позицию в строке, где парсер споткнулся, — полезно для сообщения пользователю. Первая строка заодно показывает, что `int("3")` превратил строку из JSON в число.

</details>

## Контекстные менеджеры: with

**Проблема.** Файл, сетевое соединение, блокировку нужно обязательно закрыть или освободить, даже если в середине работы случилась ошибка. Если забыть — утечки дескрипторов (`Too many open files`), зависшие блокировки.

**Решение — `with`.** Гарантирует, что ресурс будет освобождён при выходе из блока, как бы ни вышли: нормально, через `return` или через исключение.
```python
with open("deploy.log", "a") as f:     # открыть файл на дозапись
    f.write("deploy started\n")
# здесь файл уже закрыт — даже если write упал с ошибкой

# несколько ресурсов сразу
with open("in.txt") as src, open("out.txt", "w") as dst:
    dst.write(src.read().upper())
```
Без `with` пришлось бы писать `try/finally` с `f.close()` вручную.

Свой контекстный менеджер проще всего сделать через генератор и декоратор `@contextmanager`. Код до `yield` — «вход», после — «выход»:
```python
from contextlib import contextmanager
import time

@contextmanager
def timer(name):
    start = time.perf_counter()
    try:
        yield                          # здесь выполняется тело блока with
    finally:
        print(f"{name}: {time.perf_counter() - start:.2f}s")

with timer("backup"):
    time.sleep(2)                      # → backup: 2.00s
```
Ещё полезные: `tempfile.TemporaryDirectory()` (временная папка, удалится сама), `contextlib.suppress(FileNotFoundError)` (игнорировать конкретную ошибку), `threading.Lock()`.

### 🧪 Мини-задание

**Задача.** Напиши контекстный менеджер `cd(path)` — аналог `pushd`/`popd`: внутри `with` рабочая папка — `path`, после выхода — прежняя, даже если внутри блока было исключение. Проверь на временной папке, что она удаляется сама.

<details class="qa"><summary>Решение: команда и ожидаемый результат</summary>

Скопируй блок в терминал целиком:

```bash

@contextmanager

    old = os.getcwd()
    os.chdir(path)
    try:
        yield path
    finally:
        os.chdir(old)          # вернуться, даже если внутри была ошибка

with tempfile.TemporaryDirectory() as tmp:

        print("inside tmp:", os.getcwd() == os.path.realpath(tmp))
    try:
        with cd(tmp):
            raise RuntimeError("boom")

## Классы и объекты

**Зачем классы.** Чтобы объединить данные и функции, которые с ними работают. Например, «сервис» — это имя, число реплик, порты и операции «масштабировать», «проверить HA». В скриптах автоматизации классы нужны реже, чем в приложениях. Часто хватает словарей и функций, но читать и писать классы нужно уметь.

### Обычный класс
```python
class Service:
    default_port = 8080                  # атрибут КЛАССА — общий для всех экземпляров

    def __init__(self, name, replicas=1):
        # __init__ — инициализатор: вызывается при создании объекта Service(...)
        self.name = name                 # атрибуты ЭКЗЕМПЛЯРА — свои у каждого объекта
        self.replicas = replicas

    def scale(self, n):                  # метод — функция внутри класса
        if n < 0:
            raise ValueError("replicas не может быть отрицательным")
        self.replicas = n

    def __repr__(self):                  # как объект показывается при print и в отладке
        return f"Service({self.name!r}, replicas={self.replicas})"

api = Service("api", 3)                  # создать экземпляр
api.scale(5)
print(api)                               # → Service('api', replicas=5)
```
**Что такое `self`.** Ссылка на конкретный объект, у которого вызван метод. `api.scale(5)` Python превращает в `Service.scale(api, 5)`. Поэтому `self` — первый параметр каждого метода и пишется явно (в C# это неявный `this`).

**Магические (dunder) методы** — методы с двойными подчёркиваниями, через которые объект встраивается в синтаксис языка: `__init__` (создание), `__repr__`/`__str__` (печать), `__eq__` (сравнение `==`), `__len__` (`len(obj)`), `__iter__` (`for x in obj`), `__enter__`/`__exit__` (`with`).

### Наследование
```python
class StatefulService(Service):          # наследуем всё от Service
    def __init__(self, name, replicas=1, storage="10Gi"):
        super().__init__(name, replicas) # вызвать инициализатор родителя
        self.storage = storage

    def scale(self, n):                  # переопределяем метод родителя
        if n < self.replicas:
            raise ValueError("уменьшать stateful-сервис нельзя без миграции данных")
        super().scale(n)                 # и вызываем родительскую реализацию

db = StatefulService("postgres", 3)
isinstance(db, Service)                  # → True — наследник «является» родителем
```

### @property, @classmethod, @staticmethod
```python
class Service:
    def __init__(self, name, replicas):
        self.name = name
        self.replicas = replicas

    @property
    def is_ha(self):                     # вызывается как атрибут: svc.is_ha (без скобок)
        return self.replicas >= 2

    @classmethod
    def from_dict(cls, d):               # получает КЛАСС (cls), а не экземпляр
        return cls(d["name"], d.get("replicas", 1))   # альтернативный конструктор

    @staticmethod
    def valid_name(name):                # не получает ни класс, ни экземпляр
        return name.isidentifier()       # просто функция, логически относящаяся к классу

svc = Service.from_dict({"name": "api", "replicas": 3})
svc.is_ha                                # → True
```

### dataclass — класс для хранения данных без шаблонного кода
Для классов, которые в основном хранят данные, писать `__init__`, `__repr__`, `__eq__` вручную скучно. `@dataclass` сгенерирует их по аннотациям полей:
```python
from dataclasses import dataclass, field

@dataclass
class Service:
    name: str
    replicas: int = 1
    ports: list[int] = field(default_factory=list)   # НЕ ports: list = [] — та же ловушка mutable default

    @property
    def is_ha(self) -> bool:
        return self.replicas >= 2

a = Service("api", 3)
b = Service("api", 3)
print(a)          # → Service(name='api', replicas=3, ports=[])   — __repr__ сгенерирован
a == b            # → True   — __eq__ сравнивает поля (у обычного класса было бы False)
```
`@dataclass(frozen=True)` делает объект неизменяемым (и хешируемым — можно класть в set).

### Соглашения о «приватности»
В Python нет настоящих `private`. Есть соглашения:
- `_name` — «внутреннее, не трогай снаружи». Технически доступно.
- `__name` — имя искажается (name mangling) в `_ClassName__name`, чтобы наследники случайно не перезаписали. Используется редко.

## Модули, пакеты и импорт

**Модуль** — любой `.py`-файл. **Пакет** — папка с модулями (обычно с файлом `__init__.py`).
```
mytool/
  pyproject.toml
  src/mytool/
    __init__.py
    cli.py          # точка входа
    k8s.py          # функции для работы с кластером
  tests/
    test_k8s.py
```
```python

from pathlib import Path               # импорт конкретного имени: Path(...)
from mytool.k8s import get_pods        # из своего пакета
import datetime as dt                  # псевдоним
```
Избегай `from module import *`: непонятно, какие имена появились, и они могут перекрыть твои.

### `if __name__ == "__main__":`
```python
# file: cleanup.py
def cleanup(days):
    print(f"чищу старше {days} дней")

if __name__ == "__main__":
    cleanup(30)
```
Когда файл запускают напрямую (`python cleanup.py`), Python присваивает переменной `__name__` значение `"__main__"`, и блок выполняется. Когда файл *импортируют* (`from cleanup import cleanup`), `__name__` равно `"cleanup"`, и блок не выполняется. Так один файл может быть и скриптом, и библиотекой: функции можно импортировать в тесты, не запуская основную логику.

## Подсказки типов (type hints)
```python
from typing import Iterator, TypedDict

class Pod(TypedDict):
    name: str
    restarts: int

def noisy_pods(pods: list[Pod], threshold: int = 3) -> list[str]:
    return [p["name"] for p in pods if p["restarts"] > threshold]

def read_lines(path: str) -> Iterator[str]:   # генератор строк
    with open(path) as f:
        yield from f

def find(pods: list[Pod], name: str) -> Pod | None:   # может вернуть Pod или None
    return next((p for p in pods if p["name"] == name), None)
```
**Зачем, если Python их не проверяет:** IDE подсказывает методы и подсвечивает ошибки; `mypy` в CI находит баги до запуска (например, ты передал строку туда, где ждут число, или забыл обработать `None`); и это документация, которая не устаревает. В больших скриптах и командах это стандарт.

## Работа с файлами и путями
```python
from pathlib import Path

log_dir = Path("/var/log") / "app"           # оператор / склеивает пути (кроссплатформенно)
log_dir.exists(), log_dir.is_dir()
for f in log_dir.glob("*.log"):              # файлы по маске; rglob — рекурсивно
    print(f.name, f.suffix, f.stat().st_size)  # имя, расширение, размер в байтах

cfg = Path("config.yaml")
text = cfg.read_text(encoding="utf-8")       # прочитать файл целиком в строку
Path("out.txt").write_text("done\n")         # записать (перезаписать)
Path("data/raw").mkdir(parents=True, exist_ok=True)   # как mkdir -p
Path("old.log").unlink(missing_ok=True)      # удалить, не падая, если файла нет

# построчное чтение большого файла — без загрузки в память
with open("/var/log/app.log", encoding="utf-8", errors="replace") as f:
    for line in f:                           # файловый объект — сам генератор строк
        process(line)
```
Режимы `open`: `"r"` — чтение (по умолчанию), `"w"` — запись с **перезаписью** файла, `"a"` — дозапись в конец, `"rb"`/`"wb"` — бинарный режим. `errors="replace"` заменит «битые» байты вместо падения с `UnicodeDecodeError` — полезно для логов.

Почему список, а не строка с `shell=True`:

## Конкурентность: GIL, потоки, процессы, asyncio

**Задача.** Проверить доступность 500 URL. Последовательно, с таймаутом 5 секунд на каждый, это до 40 минут, а процессор при этом почти всё время ждёт ответа сети.

**GIL (Global Interpreter Lock).** Блокировка в CPython: в каждый момент Python-байткод выполняет только *один* поток процесса. Поэтому потоки не ускоряют *вычисления* (задачи, нагружающие CPU). Но во время ожидания ввода-вывода (сеть, диск, `sleep`) поток *отпускает* GIL, и работают другие потоки. Поэтому для I/O-задач потоки отлично работают.

| Тип задачи | Пример | Решение |
|---|---|---|
| I/O-bound (ждём сеть или диск) | опрос API, SSH на 100 серверов, healthcheck | `ThreadPoolExecutor` или `asyncio` |
| CPU-bound (считаем) | парсинг гигабайтов, сжатие, хеши | `ProcessPoolExecutor` (несколько процессов — у каждого свой GIL) |

Почти все DevOps-задачи — I/O-bound (большую часть времени ждут сеть или диск: запросы к API, SSH, чтение файлов), а не CPU-bound (упираются в вычисления: сжатие, разбор гигабайтов JSON). Самый простой и достаточный инструмент — пул потоков:
```python
from concurrent.futures import ThreadPoolExecutor, as_completed
import requests

def check(url):
    try:
        return url, requests.get(url, timeout=5).status_code
    except requests.RequestException as e:
        return url, f"ERROR {type(e).__name__}"

urls = [f"https://service-{i}.example.com/health" for i in range(500)]
with ThreadPoolExecutor(max_workers=50) as pool:          # 50 запросов одновременно
    futures = [pool.submit(check, u) for u in urls]       # submit запускает задачу и возвращает Future — «обещание результата»
    for future in as_completed(futures):                  # получать результаты по мере готовности
        url, status = future.result()
        if status != 200:
            print(url, status)
# 500 URL × 5 c / 50 потоков ≈ 50 секунд в худшем случае вместо 40 минут
```
Или проще, если порядок результатов важен: `results = list(pool.map(check, urls))`.

**asyncio** — другой подход: один поток, много задач, которые сами уступают управление на `await` во время ожидания. Эффективнее потоков на тысячах одновременных соединений, но требует асинхронных библиотек (`aiohttp`, `httpx`, не `requests`), и весь код по цепочке становится `async`:
```python
import asyncio
import httpx

async def check(client, url):
    r = await client.get(url, timeout=5)     # await: «пока ждём ответ — выполняй другие задачи»
    return url, r.status_code

async def main(urls):
    async with httpx.AsyncClient() as client:
        return await asyncio.gather(*(check(client, u) for u in urls))   # запустить все и дождаться

results = asyncio.run(main(urls))
```
В Python 3.13+ появилась экспериментальная сборка без GIL (free-threaded), но в проде пока используется обычная.

## Тесты: pytest
**Зачем в DevOps.** Скрипт, который удаляет снапшоты или правит DNS, без тестов — риск. Тесты на функции разбора данных и логики фильтрации ловят ошибки до прода.
```python
# src/mytool/parse.py
def parse_status(line: str) -> int:
    parts = line.split()
    if len(parts) < 9:
        raise ValueError(f"короткая строка: {line!r}")
    return int(parts[8])

# tests/test_parse.py
import pytest
from mytool.parse import parse_status

def test_parse_ok():
    line = '1.1.1.1 - - [12/Oct/2026:10:00:00 +0000] "GET / HTTP/1.1" 200 5'
    assert parse_status(line) == 200          # обычный assert — pytest покажет, что с чем не совпало

@pytest.mark.parametrize("line", ["", "garbage", "a b c"])   # один тест — много входных данных
def test_parse_bad(line):
    with pytest.raises(ValueError):           # проверить, что функция бросает исключение
        parse_status(line)

def test_reads_env(monkeypatch, tmp_path):    # фикстуры pytest передаются по имени аргумента
    monkeypatch.setenv("ENV", "test")         # подменить переменную окружения только на этот тест
    cfg = tmp_path / "cfg.yaml"               # временная папка, удалится после теста
    cfg.write_text("replicas: 2")
```
Запуск: `pytest -q` (кратко), `pytest -k parse` (только тесты с «parse» в имени), `pytest -x` (остановиться на первом падении). Внешние вызовы подменяют моками: `unittest.mock.patch`, для AWS — библиотека `moto` (поддельный AWS в памяти).

**1. Топ-10 IP по access.log и доля 5xx.**

total = errors = 0
with open("access.log", encoding="utf-8", errors="replace") as f:
    for line in f:                       # построчно — файл может быть огромным
        parts = line.split()
        if len(parts) < 9:               # пропускаем битые строки, а не падаем
            continue
        total += 1
        ips[parts[0]] += 1               # первое поле — IP клиента
        if parts[8].startswith("5"):     # девятое поле — HTTP-статус
            errors += 1

for ip, count in ips.most_common(10):
    print(f"{ip:15} {count}")
if total:
    print(f"5xx: {errors / total:.2%}")
```

**3. Сравнить два конфига: что добавлено, удалено, изменено.**
```python
def diff(old: dict, new: dict) -> dict:
    return {
        "added":   {k: new[k] for k in new.keys() - old.keys()},   # ключи только в new
        "removed": {k: old[k] for k in old.keys() - new.keys()},   # ключи только в old
        "changed": {k: (old[k], new[k]) for k in old.keys() & new.keys() if old[k] != new[k]},
    }

diff({"a": 1, "b": 2}, {"b": 3, "c": 4})
# → {'added': {'c': 4}, 'removed': {'a': 1}, 'changed': {'b': (2, 3)}}
```
Тут видно сразу три приёма: множества ключей (`keys()` поддерживает `-` и `&`), dict comprehension и кортеж для пары значений.

**4. Проверка скобок** (классика на стек):
```python
def balanced(s: str) -> bool:
    pairs = {")": "(", "]": "[", "}": "{"}
    stack = []
    for ch in s:
        if ch in "([{":
            stack.append(ch)                       # открывающую кладём в стек
        elif ch in pairs:
            if not stack or stack.pop() != pairs[ch]:
                return False                       # закрывающая не совпала с последней открытой
    return not stack                               # все открытые должны закрыться

balanced("{[()]}")   # → True
balanced("{[(])}")   # → False
```

**5. Two sum** — найти два числа, дающих в сумме target. Наивно — два вложенных цикла, O(n²). Через словарь — один проход, O(n):
```python
def two_sum(nums, target):
    seen = {}                          # число → его индекс
    for i, n in enumerate(nums):
        if target - n in seen:         # нужная «пара» уже встречалась?
            return seen[target - n], i
        seen[n] = i
    return None

two_sum([2, 7, 11, 15], 9)   # → (0, 1)
```

**6. Операционный инструмент: аудит настроек хоста.**
Типичная задача для Platform/SRE: проверить, что хост действительно настроен так, как задумано (изолированные ядра, THP, hugepages, привязка прерываний), и вернуть код ошибки, чтобы скрипт можно было вставить в проверку AMI или в CI. Приёмы, которые здесь показывают: `argparse`, `pathlib`, разбор форматов `/proc` и `/sys`, понятный вывод и JSON для машин, код возврата. Параметр `--root` позволяет тестировать скрипт на поддельном дереве файлов, без настоящего сервера.
```python
#!/usr/bin/env python3
"""Проверяет, что хост настроен под низкую задержку. Код возврата 1, если есть отклонения."""
import argparse
import json
import sys
from pathlib import Path


def parse_cpus(text: str) -> set[int]:
    """'2-5,8' -> {2, 3, 4, 5, 8}"""
    cpus = set()
    for part in text.strip().split(","):
        if not part:
            continue
        if "-" in part:
            start, end = part.split("-")
            cpus.update(range(int(start), int(end) + 1))
        else:
            cpus.add(int(part))
    return cpus


def read(root: Path, path: str) -> str:
    return (root / path.lstrip("/")).read_text().strip()


def check(root: Path, expected_isolated: set[int], min_hugepages: int) -> list[dict]:
    results = []

    def add(name, ok, actual, expected):
        results.append({"check": name, "ok": ok, "actual": actual, "expected": expected})

    isolated = parse_cpus(read(root, "/sys/devices/system/cpu/isolated"))
    add("isolated_cpus", isolated == expected_isolated, sorted(isolated), sorted(expected_isolated))

    thp = read(root, "/sys/kernel/mm/transparent_hugepage/enabled")
    mode = thp[thp.index("[") + 1:thp.index("]")]          # "always [madvise] never" -> "madvise"
    add("thp", mode in ("madvise", "never"), mode, "madvise|never")

    meminfo = dict(line.split(":", 1) for line in read(root, "/proc/meminfo").splitlines())
    hugepages = int(meminfo["HugePages_Total"])
    add("hugepages", hugepages >= min_hugepages, hugepages, f">={min_hugepages}")

    numa_balancing = read(root, "/proc/sys/kernel/numa_balancing")
    add("numa_balancing", numa_balancing == "0", numa_balancing, "0")

    # Ни одно прерывание не должно обрабатываться на изолированных ядрах
    bad_irqs = []
    for affinity in sorted((root / "proc/irq").glob("*/smp_affinity_list")):
        if parse_cpus(affinity.read_text()) & expected_isolated:
            bad_irqs.append(affinity.parent.name)
    add("irq_affinity", not bad_irqs, bad_irqs, "нет IRQ на изолированных ядрах")

    return results


def main() -> int:
    parser = argparse.ArgumentParser(description=__doc__)
    parser.add_argument("--isolated", required=True, help="ожидаемые изолированные ядра, например 2-7")
    parser.add_argument("--min-hugepages", type=int, default=0)
    parser.add_argument("--root", default="/", help="корень ФС (для тестов)")
    parser.add_argument("--json", action="store_true", help="вывод в JSON для CI")
    args = parser.parse_args()

    results = check(Path(args.root), parse_cpus(args.isolated), args.min_hugepages)
    if args.json:
        print(json.dumps(results, ensure_ascii=False, indent=2))
    else:
        for r in results:
            print(f"{'OK  ' if r['ok'] else 'FAIL'} {r['check']}: {r['actual']} (ожидается {r['expected']})")
    return 0 if all(r["ok"] for r in results) else 1


if __name__ == "__main__":
    sys.exit(main())
```
```bash
sudo ./host_check.py --isolated 2-7 --min-hugepages 1024
# → OK   isolated_cpus: [2, 3, 4, 5, 6, 7] (ожидается [2, 3, 4, 5, 6, 7])
# → OK   thp: never (ожидается madvise|never)
# → OK   hugepages: 1024 (ожидается >=1024)
# → OK   numa_balancing: 0 (ожидается 0)
# → FAIL irq_affinity: ['26'] (ожидается нет IRQ на изолированных ядрах)
echo $?   # → 1 — в конвейере образа такой хост не пройдёт проверку
```
Что обсудить на собеседовании: как протестировать (pytest с `tmp_path`, где создаётся поддельное дерево `/proc`), как добавить новые проверки, не переписывая `main` (список функций-проверок), почему выход ненулевой при любой ошибке, и как отдавать результат в Prometheus (textfile collector у node_exporter).

**Ещё для самостоятельной практики:**
- скрипт удаления EBS-снапшотов старше N дней с `--dry-run` и логированием;
- healthcheck списка URL с параллельностью и итоговым отчётом;
- CLI для GitLab API: список упавших пайплайнов за сутки по всем проектам группы (с пагинацией);
- свой Prometheus exporter на `prometheus_client`, который отдаёт метрику из какого-нибудь API.

### 1. Третье слово каждой строки — в один ряд

**Задача.** В `lines.txt` выведи третье слово каждой строки в одну строку через пробел; строки, где слов меньше трёх, пропусти.

```text
the quick brown fox
jumps over the lazy dog
a b c
only two
```

Ожидаемый вывод: `brown the c`.

<details class="qa"><summary>Решение и разбор</summary>

```python
with open("lines.txt") as f:
    thirds = [line.split()[2] for line in f if len(line.split()) >= 3]
print(" ".join(thirds))
```

```text
brown the c
```

- `for line in f` читает файл построчно — не загружает весь файл в память, это важно для больших логов.
- `line.split()` **без аргумента** режет по любой последовательности пробелов, табов и переводов строки и выбрасывает пустые куски. `[2]` — третий элемент (индексы с нуля).
- `if len(line.split()) >= 3` — фильтр в list comprehension: короткие строки пропускаются, иначе `[2]` упадёт с `IndexError`.
- `" ".join(thirds)` склеивает список строк через пробел. Альтернатива — `print(*thirds)`: звёздочка раскладывает список на отдельные аргументы, а `print` по умолчанию ставит между ними пробел.

В решении `split()` вызывается дважды. Чтобы резать строку один раз, используй оператор присваивания в выражении `:=` (Python 3.8+):

```python
with open("lines.txt") as f:
    thirds = [w[2] for line in f if len(w := line.split()) >= 3]
```

**Частая ошибка:** `line.split(" ")` с явным пробелом. Он режет по **каждому** пробелу и оставляет пустые строки: `"  a   b  c".split(" ")` даёт `['', '', 'a', '', '', 'b', '', 'c']`, и `[2]` вернёт `a`. Без аргумента — `['a', 'b', 'c']`. Это ровно та же ловушка, что `cut -d' '` в Bash.

</details>

### 2. Два самых частых слова

**Задача.** В `words.txt` найди два самых частых слова без учёта регистра и знаков препинания и выведи их с количеством.

```text
Deploy api, deploy web.
Rollback; deploy API!
restart db
```

<details class="qa"><summary>Решение и разбор</summary>

```python
import re
from collections import Counter
from pathlib import Path

text = Path("words.txt").read_text().lower()
words = re.findall(r"[a-z]+", text)
for word, count in Counter(words).most_common(2):
    print(count, word)
```

```text
3 deploy
2 api
```

- `Path(...).read_text()` читает файл целиком в строку — для небольшого файла это проще, чем цикл.
- `.lower()` — всё в нижний регистр, чтобы `Deploy` и `deploy` совпали.
- `re.findall(r"[a-z]+", text)` возвращает список всех непрерывных последовательностей латинских букв — знаки препинания и пробелы просто не попадают в результат. Для кириллицы и любых других алфавитов: `r"[^\W\d_]+"` — «буквенный символ любого алфавита» (`\w` без цифр и `_`).
- `Counter(words)` — словарь «слово → сколько раз». `most_common(2)` возвращает список пар `(слово, количество)` по убыванию.

**Частые ошибки:**
- **`text.split()` вместо регулярного выражения** — останутся `api,` и `API!` со знаками, и они посчитаются как разные слова.
- **Ручной словарь вместо `Counter`** — `if w not in d: d[w] = 0` работает, но на собеседовании от тебя ждут знания `Counter` (или хотя бы `dict.get(w, 0) + 1`).

Что могут спросить дальше: «при равных количествах — по алфавиту» → `sorted(Counter(words).items(), key=lambda p: (-p[1], p[0]))[:2]`: минус перед количеством даёт убывание, второе поле кортежа — алфавит при равенстве.

</details>

### 3. Сколько запросов на каждый HTTP-статус

**Задача.** По `access.log` (формат nginx combined) посчитай запросы по HTTP-статусам и долю 5xx.

<details class="qa"><summary>Решение и разбор</summary>

```python
from collections import Counter

statuses = Counter()
with open("access.log") as f:
    for line in f:
        parts = line.split()
        if len(parts) > 8:               # битую строку пропускаем, а не падаем
            statuses[parts[8]] += 1      # девятое поле (индекс 8) — статус
for status, count in statuses.most_common():
    print(status, count)

errors = sum(c for s, c in statuses.items() if s.startswith("5"))
total = sum(statuses.values())
if total:
    print(f"5xx: {errors} of {total} ({errors / total:.1%})")
```

```text
200 2
500 1
302 1
404 1
502 1
5xx: 2 of 6 (33.3%)
```

- `Counter()` можно увеличивать как обычный словарь: для нового ключа стартовое значение — 0, `KeyError` не будет.
- `most_common()` без аргумента — все элементы по убыванию; при равных количествах сохраняется порядок первой встречи.
- `sum(c for s, c in ...)` — генераторное выражение: суммирует количества только для статусов на `5`.
- `f"{errors / total:.1%}"` — формат процентов: умножает на 100, оставляет один знак после запятой и добавляет `%`.
- `if total:` — защита от деления на ноль на пустом файле.

**Частая ошибка — битая строка запроса.** Если вместо `"GET / HTTP/1.1"` в логе `"-"`, поля сдвигаются, и `parts[8]` — уже не статус. Надёжнее резать по кавычкам: статус — первое слово после второй кавычки.

```python
status = line.split('"')[2].split()[0]
```

Для строки `... "-" 400 0 "-" "-"` вариант со `split()` даёт `"-"`, а вариант с кавычками — `400`.

</details>

### 4. Убрать повторы, сохранив порядок

**Задача.** Выведи строки из `services.txt` (`web api web db api`) без повторов, в порядке первого появления.

<details class="qa"><summary>Решение и разбор</summary>

```python
from pathlib import Path

services = Path("services.txt").read_text().split()
print(" ".join(dict.fromkeys(services)))
```

```text
web api db
```

- `dict.fromkeys(список)` создаёт словарь, где элементы списка — ключи. Ключи словаря уникальны, а с Python 3.7 словарь **сохраняет порядок вставки** — повторы отбрасываются, порядок первого появления остаётся.
- `" ".join(...)` перебирает ключи словаря и склеивает их.

**Частая ошибка:** `set(services)` тоже убирает повторы, но порядок у множества не гарантирован. Если интервьюер просит «сохранить порядок» — это проверка как раз на это.

Вариант, который стоит уметь написать руками (его иногда просят «без встроенных трюков»):

```python
seen, result = set(), []
for s in services:
    if s not in seen:          # проверка в set — O(1), в list была бы O(n)
        seen.add(s)
        result.append(s)
```

</details>

### 5. Что есть в одном списке, но нет в другом

**Задача.** В `all.txt` все хосты, в `done.txt` — уже обновлённые. Выведи необновлённые в исходном порядке.

<details class="qa"><summary>Решение и разбор</summary>

```python
from pathlib import Path

done = set(Path("done.txt").read_text().split())
todo = [h for h in Path("all.txt").read_text().split() if h not in done]
print(" ".join(todo))
```

```text
web-2 cache-1 api-1
```

- `done` — множество: проверка `h not in done` занимает O(1), независимо от размера списка.
- List comprehension идёт по `all.txt` по порядку, поэтому порядок сохраняется.
- `.split()` без аргумента заодно убирает пустые строки и `\r` из файлов Windows — частая проблема варианта на `grep` здесь не возникает.

**Почему не просто вычитание множеств:** `set(all_hosts) - done` даст правильный набор, но в случайном порядке, например `{'cache-1', 'api-1', 'web-2'}`.

**Почему не список для `done`:** `h not in done_list` проверяет элементы по одному — O(n) на каждую проверку, а всего O(n·m). На двух списках по 100 000 хостов это минуты вместо долей секунды. Именно этот переход «список → множество» интервьюер и хочет услышать.

</details>

### 6. Среднее и максимальное время ответа

**Задача.** В `times.txt` четвёртое поле — время ответа. Выведи число запросов, среднее и самый медленный запрос с путём.

<details class="qa"><summary>Решение и разбор</summary>

```python
from pathlib import Path

rows = [line.split() for line in Path("times.txt").read_text().splitlines() if line.strip()]
times = [float(r[3]) for r in rows]
slowest = max(rows, key=lambda r: float(r[3]))
print(f"requests={len(times)} avg={sum(times) / len(times):.3f} max={slowest[3]} ({slowest[1]})")
```

```text
requests=4 avg=0.500 max=1.500 (/api)
```

- `splitlines()` режет текст на строки, `if line.strip()` выбрасывает пустые (например, последнюю после финального перевода строки).
- `float(r[3])` — поле прочитано как строка, для арифметики его нужно превратить в число. Без этого `max` сравнит строки как текст: `"9.5"` окажется больше `"10.0"`, потому что текст сравнивается посимвольно, а символ `9` больше символа `1`.
- `max(rows, key=...)` возвращает **всю строку** с максимальным значением ключа — так сразу доступен и путь `slowest[1]`.

**Частая ошибка:** деление на ноль на пустом файле. В реальном скрипте проверь `if times:` перед расчётом среднего. Для статистики есть модуль `statistics`: `statistics.mean(times)`, `statistics.median(times)`.

</details>

### 7. Фильтр по CSV

**Задача.** В `users.csv` (`name,email,age`) выведи имя и email всех, кому больше 30.

<details class="qa"><summary>Решение и разбор</summary>

```python
import csv

with open("users.csv", newline="") as f:
    for row in csv.DictReader(f):
        if int(row["age"]) > 30:
            print(row["name"], row["email"])
```

```text
alice alice@example.com
carol carol@example.com
```

- `csv.DictReader` берёт первую строку как заголовок и отдаёт каждую следующую как словарь `{"name": ..., "email": ..., "age": ...}` — обращение по имени колонки читается лучше, чем `row[2]`.
- `int(row["age"])` — модуль `csv` все значения возвращает строками; без `int()` сравнение `"34" > 30` упадёт с `TypeError`.
- `newline=""` — рекомендация документации для `csv`: модуль сам разбирает переводы строк, в том числе внутри значений в кавычках.

**Главный плюс перед awk:** `csv` правильно разбирает значения с запятой внутри кавычек. Строка `"Smith, John",j@example.com,45` превращается в `['Smith, John', 'j@example.com', '45']`, а `awk -F,` разрезал бы имя на два поля.

</details>

### 8. Перевернуть строку и порядок слов

**Задача.** Для `hello world` выведи строку задом наперёд, слова в обратном порядке и каждое слово перевёрнутым.

<details class="qa"><summary>Решение и разбор</summary>

```python
s = "hello world"
print(s[::-1])
print(" ".join(s.split()[::-1]))
print(" ".join(w[::-1] for w in s.split()))
```

```text
dlrow olleh
world hello
olleh dlrow
```

- `s[::-1]` — срез с шагом −1: от конца к началу. Работает для строк, списков и кортежей.
- `s.split()[::-1]` — сначала список слов, потом этот список задом наперёд.
- В третьей строке генератор переворачивает каждое слово, а порядок слов остаётся прежним.

**Частая ошибка:** `s.reverse()` — у строк такого метода нет, строки неизменяемые. У списков `reverse()` есть, но он меняет список на месте и возвращает `None`, поэтому `print(lst.reverse())` выведет `None`. Ещё вариант для строки — `"".join(reversed(s))`: `reversed` возвращает итератор, его нужно склеить обратно.

</details>

### 9. Самые большие файлы в каталоге

**Задача.** Найди три самых больших файла внутри `data/` вместе с подкаталогами.

<details class="qa"><summary>Решение и разбор</summary>

```python
from pathlib import Path

files = [p for p in Path("data").rglob("*") if p.is_file()]
for p in sorted(files, key=lambda p: p.stat().st_size, reverse=True)[:3]:
    print(f"{p.stat().st_size / 1024 / 1024:6.1f} MB  {p}")
```

```text
   2.9 MB  data/logs/app.log
   1.9 MB  data/logs/old.log
   1.0 MB  data/dump.sql
```

- `rglob("*")` — рекурсивный обход: все файлы и каталоги на любой глубине. `is_file()` оставляет только файлы.
- `p.stat().st_size` — размер в байтах. `sorted(..., key=..., reverse=True)` — по убыванию, `[:3]` — первые три.
- `:6.1f` в f-строке — число шириной 6 символов с одним знаком после запятой, чтобы колонка была ровной.

**Что улучшить, если спросят:**
- На реальном сервере обход упадёт на каталоге без прав доступа — оберни `stat()` в `try/except OSError` и пропускай такие файлы.
- Для огромных деревьев не нужно сортировать всё: `heapq.nlargest(3, files, key=...)` держит в памяти только три лучших.
- `is_file()` следует по символическим ссылкам — один файл может посчитаться дважды; если важно, проверяй `p.is_symlink()`.

</details>

### 10. Поменять значения в конфиге

**Задача.** В `app.conf` поставь `port=8080`, `debug=false`, а если ключа `timeout` нет — допиши `timeout=30`. Остальные строки (в том числе комментарии) не трогать.

<details class="qa"><summary>Решение и разбор</summary>

```python
from pathlib import Path


def set_keys(path, updates):
    path = Path(path)
    lines, seen = [], set()
    for line in path.read_text().splitlines():
        key = line.split("=", 1)[0].strip()
        if key in updates:
            line = f"{key}={updates[key]}"
            seen.add(key)
        lines.append(line)
    lines += [f"{k}={v}" for k, v in updates.items() if k not in seen]
    path.write_text("\n".join(lines) + "\n")


set_keys("app.conf", {"port": "8080", "debug": "false", "timeout": "30"})
print(Path("app.conf").read_text(), end="")
```

```text
host=0.0.0.0
port=8080
debug=false
timeout=30
```

- `line.split("=", 1)` — резать максимум один раз: значение `url=http://a?b=c` не развалится на лишние части. `[0].strip()` — ключ без пробелов вокруг.
- Строки, ключа которых нет в `updates` (включая комментарии `# ...`), добавляются как есть — порядок и комментарии сохраняются.
- `seen` запоминает, какие ключи уже заменены; оставшиеся дописываются в конец. Повторный запуск ничего не меняет — функция идемпотентна.
- `print(..., end="")` — файл уже заканчивается переводом строки, второй не нужен.

**Что обсудить:**
- **`configparser`** подходит для INI-файлов с секциями `[section]`, но при записи теряет комментарии — поэтому для правки «как есть» часто пишут свой разбор, как выше.
- **Атомарная запись:** если процесс упадёт посреди `write_text`, файл останется обрезанным. Надёжно — записать во временный файл рядом и переименовать через `os.replace(tmp, path)`: переименование в пределах одной файловой системы атомарное.

</details>

### 11. FizzBuzz — разминка

**Задача.** Выведи числа от 1 до 15 в одну строку: кратные 3 — `Fizz`, кратные 5 — `Buzz`, кратные обоим — `FizzBuzz`.

<details class="qa"><summary>Решение и разбор</summary>

```python
def fizzbuzz(n):
    if n % 15 == 0:
        return "FizzBuzz"
    if n % 3 == 0:
        return "Fizz"
    if n % 5 == 0:
        return "Buzz"
    return str(n)


print(" ".join(fizzbuzz(i) for i in range(1, 16)))
```

```text
1 2 Fizz 4 Buzz Fizz 7 8 Fizz Buzz 11 Fizz 13 14 FizzBuzz
```

- Отдельная функция легко тестируется: `assert fizzbuzz(15) == "FizzBuzz"` — интервьюеру это нравится.
- `range(1, 16)` — от 1 до 15: правая граница не включается.
- `return str(n)` — `join` склеивает только строки, число нужно преобразовать.

Короткий вариант, который иногда показывают «для красоты»:

```python
print(" ".join("Fizz" * (n % 3 == 0) + "Buzz" * (n % 5 == 0) or str(n) for n in range(1, 16)))
```

`True` и `False` в арифметике — это 1 и 0, поэтому `"Fizz" * True` — `"Fizz"`, а `"Fizz" * False` — пустая строка. Если обе части пустые, `or` подставляет число. На собеседовании лучше сначала написать понятную версию, а короткую показать как вариант.

</details>

## Вопросы с собеседований

**Какие типы изменяемые, а какие нет? Почему это важно?**
Неизменяемые: `int`, `float`, `bool`, `str`, `tuple`, `frozenset`, `bytes`. Изменяемые: `list`, `dict`, `set`, объекты классов. Важно по трём причинам: изменяемый объект, переданный в функцию, меняется и снаружи; ключами словаря могут быть только хешируемые (неизменяемые) объекты; изменяемое значение по умолчанию в функции разделяется между вызовами.

**Как передаются аргументы — по значению или по ссылке?**
Ни так, ни так: «по ссылке на объект» (call by sharing). Функция получает ссылку на тот же объект. Если она *изменит* изменяемый объект (`lst.append`), это будет видно снаружи. Если *перепривяжет* имя (`lst = [...]`), снаружи ничего не изменится: поменялся только локальный ярлык.

**В чём ловушка `def f(x=[])`?**
Значение по умолчанию вычисляется один раз при определении функции, и все вызовы делят один список. Правильно: `x=None`, а внутри `if x is None: x = []`.

**Разница между list, tuple, set и dict?**
List — упорядоченный изменяемый, доступ по индексу. Tuple — упорядоченный неизменяемый, хешируемый (можно ключом dict). Set — уникальные элементы, быстрый `in`, операции над множествами. Dict — ключ → значение, поиск по ключу за O(1). Поиск `in` в list — O(n), в set/dict — O(1).

**`is` против `==`?**
`==` сравнивает значения, `is` — что это один и тот же объект в памяти. `is` используют только с `None`.

**Что такое генератор и зачем он нужен?**
Объект, который выдаёт значения по одному по требованию (функция с `yield` или выражение в круглых скобках). Не хранит всю последовательность в памяти: можно обработать файл на десятки гигабайт или бесконечный поток. Проходится один раз.

**Что такое декоратор? Пример из практики?**
Функция, которая принимает функцию и возвращает обёрнутую с дополнительным поведением. `@decorator` — сокращение для `func = decorator(func)`. Примеры: retry с экспоненциальной задержкой для вызовов API, замер времени, логирование вызовов, кэширование (`@lru_cache`), проверка прав.

**Что такое GIL? Как ускорить скрипт, который опрашивает 500 серверов?**
GIL — блокировка CPython, из-за которой в один момент байткод выполняет только один поток. Но во время ожидания I/O поток отпускает GIL. Опрос серверов — I/O-bound задача, поэтому подойдут `ThreadPoolExecutor` или `asyncio`. Для CPU-bound задач нужны процессы (`ProcessPoolExecutor`).

**Что такое `*args` и `**kwargs`?**
`*args` собирает лишние позиционные аргументы в кортеж, `**kwargs` — лишние именованные в словарь. Используются в обёртках и декораторах, чтобы принять любые аргументы и передать их дальше.

**Чем поверхностная копия отличается от глубокой?**
`copy.copy(x)` / `lst.copy()` / `lst[:]` создают новый внешний контейнер, но вложенные объекты остаются общими: изменение вложенного списка видно в обеих копиях. `copy.deepcopy(x)` рекурсивно копирует всё.

**Зачем `if __name__ == "__main__":`?**
Блок выполняется только при прямом запуске файла, но не при импорте. Так файл может быть и скриптом, и модулем: его функции можно импортировать в тесты или другие скрипты.

**Как безопасно запускать shell-команды из Python?**
`subprocess.run([...])` со списком аргументов, `check=True`, `timeout=...`, `capture_output=True, text=True`. Не использовать `shell=True` с внешними данными (shell-инъекции) и не использовать `os.system`.

**Чем опасен `yaml.load`?**
YAML умеет описывать создание Python-объектов, и `yaml.load` с небезопасным загрузчиком может выполнить код из файла. Нужно использовать `yaml.safe_load`.

**Как обработать файл, который не помещается в память?**
Читать построчно (`for line in f`), строить обработку на генераторах, читать блоками фиксированного размера (`f.read(1024 * 1024)`), для JSON Lines или CSV — потоковое чтение. Никаких `read()` и `readlines()` целиком.

**List comprehension или обычный цикл?**
Comprehension — для простого построения коллекции: короче и быстрее. Обычный цикл — когда логика сложная, несколько условий или есть побочные эффекты (запись, вызовы API).

**Как организовать зависимости Python-проекта?**
Отдельный venv (или uv) на проект, зависимости в `pyproject.toml`, зафиксированные версии в lock-файле или `requirements.txt` с `==`, `.venv` в `.gitignore`, никаких `sudo pip install` в системный Python.

**Как сделать скрипт удобным для эксплуатации?**
`argparse` с `--help` и `--dry-run`, `logging` вместо `print`, понятные коды выхода, конфигурация через переменные окружения и аргументы (без хардкода), таймауты на все сетевые вызовы, retry с backoff, идемпотентность (повторный запуск ничего не ломает), тесты на логику.

**Почему `0.1 + 0.2 != 0.3`?**
Float хранится в двоичном виде, и 0.1 в двоичной системе — бесконечная дробь, поэтому хранится приближённо. Сравнивать float нужно через `math.isclose`, для денег использовать `Decimal`.

**Что выведет код и почему?**
```python
funcs = [lambda: i for i in range(3)]
print([f() for f in funcs])
```
`[2, 2, 2]`, а не `[0, 1, 2]`. Лямбда запоминает не *значение* `i`, а *переменную* `i` (позднее связывание, late binding), и к моменту вызова цикл закончился и `i == 2`. Исправление: `lambda i=i: i` — значение по умолчанию вычисляется в момент создания лямбды.
